# Промт для Kiro

Открой в Kiro папку `/Users/mark/Desktop/gym-app` и вставь это первым сообщением.

---

Проект — личный офлайн-дневник тренировок, React + TypeScript + Vite, данные
в IndexedDB через Dexie, PWA. В репозитории уже лежит контекст:

- `.kiro/steering/` — что это за приложение, стек, жёсткие ограничения и структура.
  Прочитай все три файла прежде чем что-то менять.
- `.kiro/specs/profiles/` — спецификация задачи: требования, устройство и задачи.

Задача: реализовать спецификацию `profiles` — профили пользователей и сборку
программы под человека.

Важное, что легко нарушить:

1. **Расчётная часть уже написана и покрыта тестами** — `src/lib/anthro.ts`
   и `src/lib/generator.ts`. Не переписывай их, сделай вокруг них хранение и экраны.
2. **Миграция базы — самое опасное место.** Это единственная копия дневника,
   бэкапа в облаке нет. Сначала напиши тест на то, что данные переживают миграцию.
3. **Никаких `alert`, `confirm`, `prompt`** — они вешают страницу. Подтверждения
   делаются экраном или двухшаговой кнопкой.
4. **Никаких сторонних библиотек** — в приложении их нет вообще, и это осознанно.
5. **Программу владельца не подменять расчётной** — она выверена, расчёт нужен
   только для новых профилей.

Проверяй не на глаз, в проекте есть инструменты:

```bash
npm run build
node --test src/lib/progression.test.ts
node --test src/lib/generator.test.ts
node scripts/walkthrough.mjs --sessions=2
```

Пуш в `main` автоматически собирает, прогоняет тесты и публикует на
`https://ssfnails.github.io/gym-app/`. Если тесты падают — публикации не будет.

Начни с чтения steering-файлов и спецификации, потом покажи план по задачам
из `tasks.md` и дождись подтверждения, прежде чем писать код.
